Install the Android emulator

10–20 min

TapHerd controls any Android device your computer can reach with Android's adb tool. The easiest is Google's free Pixel emulator, which comes with Android Studio. Already have an Android phone? You can use it instead.

15 GBfree disk space for Android Studio and one system image
8 GBof RAM, or 16 GB to run two or three emulators
VirtualizationBuilt in on every MacTurned on in BIOS (VT-x or AMD-V)KVM available at /dev/kvm
First, turn on virtualization. Restart into your BIOS or UEFI and enable Intel VT-x or AMD-V (sometimes called SVM). Back in Windows, open Turn Windows features on or off, tick Windows Hypervisor Platform, and restart.
First, check KVM. The emulator is unusably slow without it. 
ls -l /dev/kvm                 # should exist
sudo usermod -aG kvm "$USER"   # then log out and back in
  1. Download Android Studio from developer.android.com/studio. Pick Mac with Apple chip (M1 or later) or Mac with Intel chip. Open the .dmg and drag Android Studio into Applications. Run the .exe installer and keep the default components, including Android Virtual Device. Extract the .tar.gz, for example into ~/android-studio, and run bin/studio.sh.
  2. Run the setup wizard. Choose Standard, accept the licenses, and let it download the Android SDK, the emulator, and Platform-Tools (which includes adb).
  3. Open Device Manager. On the welcome screen, click More Actions → Virtual Device Manager.
  4. Create a device. Click + → Create Virtual Device and pick a Pixel phone that shows the Play Store icon.
  5. Pick a system image. Choose a Google Play image at API 34 or later. On Apple chips, the architecture must be arm64-v8a. On Intel Macs, use x86_64. Use x86_64. On Arm laptops (Snapdragon), use arm64-v8a. Use x86_64 on Intel and AMD, or arm64-v8a on Arm. Click the download arrow next to it and wait.
  6. Name it and start it. Call it TapHerd_Pixel_1, finish, and press the Run (play) button. The first boot takes a minute or two.
  7. Sign in to the Play Store on the emulator if you want to install apps like TikTok, Instagram, or YouTube. Settings, Chrome, and Maps work without signing in.

For people who'd rather not install Android Studio. Android Studio is the path we test; these commands follow Google's documented tools but haven't been run end to end by us on every system yet.

brew install --cask temurin android-commandlinetools
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
yes | sdkmanager --licenses
sdkmanager "platform-tools" "emulator" "system-images;android-34;google_apis_playstore;arm64-v8a"
avdmanager create avd -n TapHerd_Pixel_1 -d pixel_7 \
  -k "system-images;android-34;google_apis_playstore;arm64-v8a"
"$ANDROID_HOME/emulator/emulator" -avd TapHerd_Pixel_1 &

On an Intel Mac, replace arm64-v8a with x86_64 in both places, and /opt/homebrew with /usr/local.

  2. Download Command line tools only for Windows from developer.android.com/studio. Unzip it so the folder is %LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest.
  3. In a new PowerShell window:

Check the emulator is visible

Once the home screen shows, run:

adb devices -l

You see a line like emulator-5554 device product:sdk_gphone64_arm64 …

adb not found? The TapHerd installer in step 2 offers to install it, or add Android's platform-tools folder to your PATH (~/Library/Android/sdk/platform-tools) (%LOCALAPPDATA%\Android\Sdk\platform-tools) (~/Android/Sdk/platform-tools).

Run two or three emulators at once

In Device Manager, create TapHerd_Pixel_2 and TapHerd_Pixel_3 with the same phone and image, and press each one's Run (play) button. Or start them from a terminal:

SDK="$HOME/Library/Android/sdk"
"$SDK/emulator/emulator" -avd TapHerd_Pixel_1 &
"$SDK/emulator/emulator" -avd TapHerd_Pixel_2 &
$sdk = "$env:LOCALAPPDATA\Android\Sdk"
Start-Process "$sdk\emulator\emulator.exe" "-avd TapHerd_Pixel_1"
Start-Process "$sdk\emulator\emulator.exe" "-avd TapHerd_Pixel_2"
SDK="$HOME/Android/Sdk"
"$SDK/emulator/emulator" -avd TapHerd_Pixel_1 &
"$SDK/emulator/emulator" -avd TapHerd_Pixel_2 &

Each needs about 4 GB of memory. If your computer slows down, run two.

Use your own Android phone instead
  1. Open Settings → About phone and tap Build number seven times.
  2. Open Settings → System → Developer options and turn on USB debugging.
  3. Connect it with a data cable (some cables only charge), unlock it, and accept Allow USB debugging. Tick Always allow.

Most phones need their maker's USB driver on Windows. Pixel phones use the Google USB Driver from Android Studio's SDK Manager.

Install TapHerd

1–2 min

Open Terminal (press ⌘ Space, type Terminal) and paste:

curl -LsSf https://raw.githubusercontent.com/asuopys/tapherd/main/scripts/install.sh | sh

Open PowerShell from the Start menu. You don't need administrator rights. Paste:

irm https://raw.githubusercontent.com/asuopys/tapherd/main/scripts/install.ps1 | iex

Open a terminal and paste:

curl -LsSf https://raw.githubusercontent.com/asuopys/tapherd/main/scripts/install.sh | sh

The installer:

  • Installs uv, a Python tool manager, for your user only.
  • Checks for adb. If it's missing, it shows the install command and asks first. Linux package managers need sudo; it explains why before asking.
  • Installs TapHerd from PyPI and runs tapherd doctor.
Prefer to install by hand?

Install uv, then:

uv tool install tapherd
tapherd doctor

If uv says TapHerd wasn't found right after a release, use uv tool install --exclude-newer-package tapherd=false tapherd. Recent uv versions wait a few days before installing new uploads.

Open a new terminal window afterwards so the tapherd command is found.

Check everything

30 sec

With the emulator or phone on, run:

tapherd doctor

You should see something like this. Your serials may differ.

Python 3.11.18
Android Debug Bridge version 1.0.41
Active and online: emulator-5554
TapHerd Free supports up to 3 active devices and 3 concurrent operations.
Ready. Next, connect your AI: tapherd config mcp --client claude-code (or codex, claude-desktop, cursor).

If doctor says no device, unauthorized, or offline, it prints the next command to run. The fixes are below.

4

Connect your AI

2 min

TapHerd prints the exact settings for your AI app, then tells you where to paste them. Pick your app:

  1. In your project folder, save the settings as .mcp.json: 
    tapherd config mcp --client claude-code > .mcp.json
  2. Start claude in that folder and approve the tapherd server when asked.
  3. Type /mcp to check it shows as connected.
  1. Print the settings: 
    tapherd config mcp --client claude-desktop
  2. In Claude Desktop, open Settings → Developer → Edit Config. That opens ~/Library/Application Support/Claude/claude_desktop_config.json. %APPDATA%\Claude\claude_desktop_config.json. nothing: Claude Desktop isn't available on Linux. Use Claude Code, Codex, or Cursor.
  3. Add the tapherd entry inside mcpServers. If other servers are there, keep them.
  4. Quit Claude Desktop completely and open it again.
  1. Print the settings: 
    tapherd config mcp --client codex
  2. Add the [mcp_servers.tapherd] block to %USERPROFILE%\.codex\config.toml. ~/.codex/config.toml. ~/.codex/config.toml.
  3. Start a new Codex session.
  1. Print the settings: 
    tapherd config mcp --client cursor
  2. Add the tapherd entry to %USERPROFILE%\.cursor\mcp.json ~/.cursor/mcp.json ~/.cursor/mcp.json for every project, or .cursor/mcp.json for one.
  3. Reload Cursor and check TapHerd is enabled in its MCP settings.

Always paste what your tapherd config mcp prints. It points at the Python and adb on your computer. All details

5

Your first AI tap

1 min

Ask your AI:

Use TapHerd to list my devices. On the first one, open Settings, read the screen, tap Network & internet, and tell me what opened.

Settings opens on the device, then Network & internet. Your AI tells you what it sees.

That's it. Your AI can now read the screen, tap, swipe, type, and open apps on your Android devices. See all 15 tools

Post a video

optional

Once you're signed in to your own accounts on the device, your AI can post for you. TapHerd copies the video from your computer, gets the app ready, and cleans up afterwards.

  1. Put the video somewhere your AI can read, such as your project folder.
  2. Ask your AI something like: 
    Using TapHerd, copy launch.mp4 to my phone and post it to TikTok, Instagram Reels, and YouTube Shorts. Write a caption and tags for each, and post them publicly. Delete the copy from the phone when you're done.
  3. Watch it work. It uses push_media to copy the file, prepare_app to allow photo access and turn off camera and microphone prompts, taps through each app, and finishes with remove_media.

Your AI publishes each post with the visibility you ask for, such as Public, Friends, or Only you. If you don't say, it posts publicly. App screens change often, so your AI checks each screen before tapping. Only post to accounts you own. Acceptable use

If something's wrong

No device found

Make sure the emulator shows its home screen, then run adb devices -l. You should see emulator-5554 device.

unauthorized

Unlock the phone and accept Allow USB debugging. No prompt? Run adb kill-server, then adb devices.

offline

Run adb reconnect offline, or restart the emulator from Device Manager.

The emulator won't start

Check the image architecture matches your computer, free up memory, or choose Cold Boot Now in Device Manager.

My AI doesn't see TapHerd

Check the file is valid JSON or TOML with no trailing commas, and fully restart the app. Claude Desktop must be quit, not just closed.

tapherd: command not found

Open a new terminal. Still missing? Run uv tool update-shell and open another one.

More fixes are in Troubleshooting. Still stuck? Open an issue with the output of tapherd doctor, and remove any account names first.
